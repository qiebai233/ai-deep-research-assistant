# 示例研究问题

> 报告质量在很大程度上取决于**问题是否具体、可验证**。下面 10 个问题覆盖不同领域与难度，
> 可直接复制使用；`推荐深度` 是该问题通常需要的调研量级。

## 快速开始

```bash
# 离线演示（不用 key，输出确定性示例内容，仅用于体验流程）
deepresearch run "固态电池 2025 产业化进展与主要瓶颈" --demo

# 真实调研（需先配置 LLM，见 docs/quickstart.md；搜索建议 Tavily）
deepresearch run "固态电池 2025 产业化进展与主要瓶颈" --depth deep
```

> `--depth quick|standard|deep` 对应不同的子问题数、来源数与反思轮数：
> quick ≈ 3 子问题 / 8 来源 / 1 轮，standard ≈ 5 / 14 / 2，deep ≈ 7 / 24 / 3。
> 详见 [docs/configuration.md](../docs/configuration.md#深度预设)。

## 三个适合快速试跑的问题

| 研究问题 | 推荐深度 | 说明 |
| --- | --- | --- |
| 什么是检索增强生成（RAG）？它的典型架构与主要局限是什么？ | `quick` | 概念清晰，适合验证安装与配置是否正常 |
| 2025 年主流开源编程模型（DeepSeek / Qwen / Llama 系列）各自的特点是什么？ | `quick` | 模型迭代快，注意来源发布时间 |
| 远程办公对团队协作效率的影响，现有研究结论是否一致？ | `standard` | 适合观察报告如何呈现「证据冲突」 |

## 提问建议

1. **写清范围与时间**：加上年份、地域、行业限定，例如「2025 年」「中国市场」「面向中小企业」。
2. **拆成可回答的子问题**：问题越具体，Planner 拆解越准，引用也越集中。
3. **要求对比或判断**：如「主要差异」「关键瓶颈」「是否已证伪」，比开放式问题更容易得到结构化结论。
4. **争议话题要保留反面证据**：明确要求「哪些说法被证伪/仍存争议」，报告会尽量覆盖冲突来源。
5. **别把结论写进问题**：避免「为什么 X 是最好的」这类预设结论的提问方式。

## 不同场景的参数组合

```bash
# 快速摸底：最少调用、8 个来源
deepresearch run "某个新概念是什么" --depth quick

# 常规研究：5 个子问题、2 轮反思（默认）
deepresearch run "某行业的现状与趋势" --depth standard

# 深度报告：7 个子问题、3 轮反思、最多 24 个来源
deepresearch run "某技术路线的可行性与时间表" --depth deep

# 只用模型知识、不联网（无外部引用）
deepresearch run "某概念的通俗解释" --search none

# 限定预算（模型较贵或不确定时）
deepresearch run "某问题" --max-cost 0.05 --max-seconds 180 --max-sources 10

# 英文报告
deepresearch run "What are the main bottlenecks of solid-state batteries?" --lang en
```
